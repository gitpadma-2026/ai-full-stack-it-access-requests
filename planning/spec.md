# Source-grounded requirements

Each row states one externally checkable obligation from the supplied brief, requirements, policy or schema. IDs use the consistent form `R-01`, `R-02`, `R-03`, …; existing IDs R-01–R-142 are retained. Related rules may share a source quote, but each row has its own verification outcome. Routing tuples and record shapes are checked as one outcome.

The Source column names the file, heading/rule or JSON pointer, and exact quoted text. Schema line fragments are quoted separately where necessary; `<br>` separates those fragments. Supplied messages provide test evidence, not additional policy requirements.

Checks describe how to verify an obligation, not a claim that verification passed. Named tests are in the current repository; inspections supply details those tests do not assert. Run the offline suite from the repository root with `env -u API_KEY python3 -m unittest discover -s tests -v`. Implementation choices, test scenarios and inspection commands in Check are verification methods, not additional requirements. No application or test changes are part of this review.
