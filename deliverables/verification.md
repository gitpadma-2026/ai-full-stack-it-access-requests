- Automated suite: `planning/test-run.txt` is the canonical full-run record, copied exactly from `planning/remaining-suite.txt` after the 56-test pass; `planning/test-run-legacy.txt` preserves the former 38-test record. Tests use source-grounded expectations and mocks/fake HTTP only, with API_KEY unset. Credential tests patch the lookup to a test sentinel; they never read a real key. Child interpreters and in-process integration tests block network calls. No live model was called.

Exact expected spans, null cases and evidence are in `tests/ground_truth.json` and `planning/plan.md`.
- Recovery: tests expire and reclaim a lease, reject a stale completion, renew a live lease, retain earlier success when the latest attempt fails, and prevent an older source's completion from replacing the latest attempt. `test_process_interruption_resume` kills an isolated child after it durably claims a blocked mock call, advances only its test lease to expiry, and resumes in another interpreter. It checks that the completed first document retains its exact attempt/hash/result and the unfinished second document completes. `test_service_recovery_preserves_completed` retries only a failed document and preserves unrelated success. No actual machine power cut is simulated.
- Shared operation: two subprocesses resume one database concurrently. Assert exactly 20 claims/completed records and no duplicates. `test_concurrent_history_audit` adds a source revision and checks all 21 attempts and 63 enqueue/claim/completion events, source hashes, immutable configuration keys, claim tokens and latest pointers. A separate blocked-provider test asserts a fast result becomes inspectable while a slow one remains running. SQLite is tested on one host only.
- Revision/reuse: unchanged rerun creates no new attempt; byte-only JSON changes create a new hash/result/history record; a subsequent explicit read-to-write source edit changes the current permission and security routing while retaining the earlier read result; model, prompt, policy and schema changes invalidate reuse. A partial batch preserves previously ingested documents.
- Failures: provider exceptions, malformed exports, refusals, interrupted outputs, malformed JSON, extra/missing fields, bad scalar/array types, invalid enum/calendar dates and invented quotes fail explicitly. Failed outputs have null extraction and retry routing.
- Provider contract: fake HTTP asserts model/schema/store/request format, explicit authentication header isolation, retry on 429/timeouts, bounded calls, no retry on 401 and credential-safe error messages. It does not establish account model access or real API compatibility through a live call. Numeric Retry-After is supported; HTTP-date Retry-After falls back to bounded backoff.
- Export: compare document_id, attempt_id, source hash and routing across linked files. `test_concurrent_export_snapshot` pauses an export after its database snapshot, commits a source revision and overlaps another exporter; readers verify each selected immutable generation's checksums and queue/extraction agreement. Required-field tests cover successful and failed records and producing-provider provenance over fake HTTP. Root copies alone do not provide an atomic multi-file read.
- Accuracy: observed mock scalar matches 252/252 and routing matches 63/63 with zero exact-match differences. This is agreement with authored mock labels, not live quality evidence. Source quote selection/issue prose is not included in the denominator. Factual error classification still requires human comparison to original messages.

## Observed workload

`planning/workload.json` records the current 2,000-document smoke run with four workers, its runtime, elapsed enqueue/processing times and peak active mock calls. Assertions require 2,000 terminal current records, exactly 2,000 claims, zero errors, at most four simultaneous calls and 2,000 identifier-mismatch clarifications. Each input deliberately repeats IT-001's known message under an independent filename; the provider replays IT-001's saved reply with network blocked. The full suite separately checks the same 2,000-document behavior. This measures scheduling, durable writes, validation and routing for repeated mock data. It does not measure semantic generalization, production latency, provider quota behavior or multi-host scaling. Earlier timings were 11.065 seconds enqueue and 10.655 seconds processing; those are historical observations before the routing repair.

The application uses local SQLite WAL, short write transactions, immutable attempt settings, leases/heartbeats and fencing. It supports at-least-once remote calls after interruption, not exactly-once billing. Live start pacing is per process, so operators must coordinate the shared quota. Different source revisions are ordered by intake transaction, not exported_at. Histories and snapshot generations have no automatic retention/pruning. Policy rules are implemented in the deterministic router; changed business rules require code/test updates before refreshed routing is trusted.

No load test against a live provider, exhaustive injection defense test, real host-crash test, cross-host deployment test, long-duration disk-failure test or live-model accuracy evaluation was performed. Source-derived mocks verify the application pipeline and response handling; they do not prove that an unseen model response has extracted the correct meaning. Exact supporting quotes provide evidence to inspect, not proof that every scalar is semantically supported.
